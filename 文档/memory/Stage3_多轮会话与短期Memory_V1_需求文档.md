# 多轮会话与短期 Memory V1 — 需求文档

## 1. 项目背景

当前智能客服已经完成：

- RAG 知识库问答；
- MCP 订单查询；
- RAG + MCP 组合回答；
- DeepSeek 最终答案生成；
- `/chat` 主链路打通。

目前的问题是，每一次用户提问仍然基本被当成独立请求处理。

例如：

```text
用户：帮我查 TEST1001
系统：TEST1001 当前待发货

用户：那它一般多久发货？
```

第二句话里的“它”需要依赖上一轮对话才能正确理解。

因此下一阶段需要增加：

> **多轮会话 + 短期 Memory**

只解决当前会话里的上下文记忆，不做长期用户记忆。

---

## 2. 需要什么技术

这一阶段不需要新增大型框架。

继续使用现有技术：

- FastAPI
- Python
- DeepSeek
- 现有 RAG Pipeline
- 现有 MCP Client / MCP Server

新增的核心能力有 4 个：

1. **chat_id**
   - 给每个会话一个唯一 ID；
   - 用来区分不同会话。

2. **History**
   - 保存当前会话最近几轮用户和系统消息；
   - 后续问题可以参考前文。

3. **Session State**
   - 保存关键业务状态；
   - 例如当前订单号 `TEST1001`、上一次意图等。

4. **Context-aware Router**
   - Router 判断当前问题时，不只看当前 Query；
   - 还可以参考 History 和 Session State。

V1 可以先使用 Python 内存结构保存 Session，不要求立即接 Redis 或数据库。

---

## 3. 实现什么样的需求

完成以后需要支持以下多轮场景。

### 第一轮

```text
用户：帮我查 TEST1001
```

系统：

```text
TEST1001 当前待发货。
```

同时保存：

```text
order_id = TEST1001
```

### 第二轮

```text
用户：那一般多久发货？
```

系统能够知道当前仍然在讨论 `TEST1001`，并调用 RAG 查询发货规则。

### 第三轮

```text
用户：那它现在是不是已经超时了？
```

系统能够结合：

```text
Session Memory
+
MCP 订单数据
+
RAG 发货规则
```

生成最终回答。

同时，不同 `chat_id` 之间的会话不能互相污染。

---

## 4. 最终结果是什么，能否实现需求

本阶段完成后，智能客服将从：

```text
每句话独立处理
```

升级为：

```text
同一个 chat_id
↓
记住最近对话
↓
记住当前订单等关键状态
↓
理解“它、这个订单、刚才那个”等上下文
↓
继续调用 RAG / MCP
↓
返回连续、正确的回答
```

最终需要稳定实现：

```text
第一轮：查 TEST1001
第二轮：那它一般多久发货？
第三轮：那现在是不是已经超时了？
```

三轮都能够理解为同一笔订单，并正确调用对应能力。

**这一需求可以实现。**

当前项目已经具备 RAG、MCP、Router 和 DeepSeek，下一阶段主要是在现有主链上增加会话状态管理，不需要重写现有系统。
