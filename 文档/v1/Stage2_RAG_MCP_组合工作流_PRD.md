# RAG + MCP 组合工作流 V1 — 需求文档

## 1. 背景

当前项目已经完成：

- RAG 知识库问答；
- MCP 订单查询；
- `/chat` 统一入口；
- RAG / MCP 路由判断；
- MCP 异常与 RAG 的故障隔离。

目前系统只能做到：

```text
RAG 或 MCP
```

下一阶段需要解决的问题是：

> 一个用户问题同时需要“订单实时数据”和“知识库规则”时，系统能够同时使用 RAG 和 MCP，并返回一个统一答案。

---

## 2. 要做什么

新增一条：

```text
rag_mcp
```

组合链路。

例如用户输入：

```text
TEST1001 现在是什么状态？一般多久发货？
```

系统需要：

```text
/chat
↓
Router
↓
rag_mcp
↓
MCP 查询 TEST1001 当前订单状态
+
RAG 查询正常发货规则
↓
组合结果
↓
生成最终回答
```

这一阶段只实现这种最小组合能力。

普通知识问题继续只走 RAG。

普通订单问题继续只走 MCP。

暂时不增加更多 MCP Tool，也不做 Agent、复杂 Workflow 或性能优化。

---

## 3. 输出什么结果

完成后，系统能够处理三类问题：

### 纯知识问题

```text
一般多久发货？
```

结果：

```text
RAG → 知识库答案
```

### 纯订单问题

```text
TEST1001 现在是什么状态？
```

结果：

```text
MCP → 订单实时数据
```

### 组合问题

```text
TEST1001 现在是什么状态？一般多久发货？
```

结果类似：

```text
订单 TEST1001 当前状态为待发货。

根据平台发货规则，普通商品通常会在付款成功后 24 小时内发出。
```

当组合问题能够稳定完成：

```text
Router
↓
RAG + MCP
↓
统一回答
```

即可认为本阶段完成。
