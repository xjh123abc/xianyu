# Web 智能客服技术文档

## 1. 技术目标

这一阶段只做一件事：

> 给现有的智能客服后端增加一个可以在浏览器中使用的 Web 页面。

现有的 FastAPI、RAG、MCP、DeepSeek、Answer Reliability 等后端能力继续保留，不重新实现。

前端只负责：

- 接收用户输入；
- 调用后端 `/chat` 接口；
- 展示 AI 回复；
- 展示订单 / 物流结果；
- 在无法回答时提示转人工。

---

## 2. 使用的技术

前端使用：

- **Vue 3**：负责整个页面和交互逻辑；
- **Vite**：负责创建和启动 Vue 项目；
- **TypeScript**：约束接口数据和前端变量类型；
- **Element Plus**：提供输入框、按钮、卡片等 UI 组件；
- **Axios**：调用 FastAPI 后端接口。

后端继续使用当前项目：

- FastAPI；
- ChatService；
- RAG；
- MCP；
- DeepSeek；
- Answer Reliability。

---

# 3. 实现顺序

## 第一步：创建前端项目

在现有项目根目录下新增一个前端目录，例如：

```text
ecommerce-ai-customer-service/
├─ app/
├─ data/
├─ tests/
├─ ...
└─ frontend/
```

前端项目放在 `frontend` 中，不和 FastAPI 代码混在一起。

使用 Vite 创建 Vue 3 + TypeScript 项目。

创建完成后，先不要写客服功能。

第一步只验证：

```text
npm run dev
```

可以正常启动，并且浏览器可以打开 Vue 默认页面。

### 这一步完成标准

```text
http://localhost:5173
```

可以正常打开。

---

## 第二步：安装前端需要的依赖

安装：

```text
Element Plus
Axios
```

Element Plus 用来做：

- 按钮；
- 输入框；
- 卡片；
- 标签；
- 加载状态。

Axios 用来调用 FastAPI。

### 这一步完成标准

Vue 页面中可以正常使用 Element Plus 的按钮，并且项目没有依赖报错。

---

## 第三步：先搭出客服页面结构

这一阶段先只做静态页面，不接后端。

页面只保留三个主要区域。

### 1. 顶部

展示：

- 智能客服名称；
- AI 客服在线状态；
- 转人工按钮。

### 2. 左侧快捷服务

保留：

- 在线咨询；
- 查订单；
- 查物流；
- 退换售后。

### 3. 中间聊天区域

包含：

- AI 欢迎语；
- 用户消息；
- AI 消息；
- 底部输入框；
- 发送按钮。

页面结构大致为：

```text
┌───────────────────────────────────────────┐
│ 智能客服        AI 客服在线      转人工   │
├──────────┬────────────────────────────────┤
│ 在线咨询 │                                │
│ 查订单   │           聊天区域             │
│ 查物流   │                                │
│ 退换售后 │                                │
│          │                                │
│          ├────────────────────────────────┤
│          │ 输入问题……              发送   │
└──────────┴────────────────────────────────┘
```

### 这一步不要做

先不要：

- 调用 `/chat`；
- 写 RAG 逻辑；
- 写 MCP 逻辑；
- 写复杂动画；
- 写登录；
- 写后台管理。

### 这一步完成标准

打开网页以后，客服页面布局完整，看起来已经像一个正常客服页面。

---

# 4. 第四步：建立前端聊天数据结构

页面有了以后，再开始处理聊天。

前端需要保存一个聊天消息列表，例如：

```text
messages
```

每条消息至少包含：

```text
role
content
type
```

可以理解为：

```json
{
  "role": "user",
  "content": "商品多久发货？",
  "type": "text"
}
```

AI 消息：

```json
{
  "role": "assistant",
  "content": "普通现货商品通常会在付款成功后发出。",
  "type": "text"
}
```

以后如果需要展示订单卡片，可以使用：

```json
{
  "role": "assistant",
  "type": "order",
  "content": "已查询到订单信息"
}
```

### 为什么要先建立 messages

因为聊天页面本质上就是：

```text
messages
↓
Vue 循环展示
↓
一条一条显示在页面上
```

用户发送一条，就往 `messages` 中增加一条。

AI 回答以后，再增加一条。

### 这一步完成标准

暂时不调用后端。

点击发送后，用户自己输入的内容可以先显示在聊天窗口中。

---

# 5. 第五步：建立 Axios 接口文件

不要把所有接口代码直接写在页面里。

建议单独创建一个接口文件，例如：

```text
src/
├─ api/
│  └─ chat.ts
├─ components/
├─ App.vue
└─ main.ts
```

`chat.ts` 专门负责调用：

```text
POST /chat
```

前端发送的数据使用当前后端需要的格式：

```json
{
  "query": "TEST1003 现在是什么状态？",
  "chat_id": "chat_xxx"
}
```

Axios 的任务就是：

```text
Vue
↓
Axios
↓
FastAPI /chat
↓
取得 JSON
↓
返回给 Vue
```

### 这一步完成标准

在前端写一个测试按钮，可以成功请求 FastAPI `/chat`，并在浏览器控制台中看到后端返回的 JSON。

---

# 6. 第六步：处理前后端地址和 CORS

开发阶段通常会出现两个地址：

```text
Vue
http://localhost:5173
```

```text
FastAPI
http://localhost:8000
```

因为端口不同，浏览器会把它们看成两个不同来源。

所以 FastAPI 需要允许前端地址访问。

开发阶段允许：

```text
http://localhost:5173
```

前端 Axios 请求地址可以先配置为：

```text
http://127.0.0.1:8000
```

最好统一放到一个配置文件或环境变量中，不要在很多页面里重复写。

### 这一步完成标准

Vue 页面可以成功请求 FastAPI，不再出现 CORS 错误。

---

# 7. 第七步：打通发送消息主流程

这一步才真正把聊天框和 `/chat` 接起来。

用户发送消息时，执行以下流程：

```text
用户输入问题
↓
点击发送
↓
把用户消息加入 messages
↓
显示“正在回答”
↓
Axios POST /chat
↓
FastAPI 处理
↓
得到返回结果
↓
把 AI 回答加入 messages
↓
页面自动显示
```

例如：

用户输入：

```text
商品多久发货？
```

前端发送：

```json
{
  "query": "商品多久发货？",
  "chat_id": "chat_xxx"
}
```

后端返回：

```json
{
  "answer": "普通现货商品通常会在付款成功后的 24 小时内发出。",
  "can_answer": true
}
```

前端最终只展示：

```text
普通现货商品通常会在付款成功后的 24 小时内发出。
```

### 注意

前端不要展示：

- RAG；
- RRF；
- Rerank；
- MCP Tool；
- rerank score；
- route 调试信息。

这些属于后端内部信息。

### 这一步完成标准

在网页中输入一个知识库问题，可以看到真实后端回答。

---

# 8. 第八步：处理 chat_id

每一轮连续对话必须使用同一个 `chat_id`。

例如：

第一轮：

```json
{
  "query": "TEST1003 现在是什么状态？",
  "chat_id": "chat_001"
}
```

第二轮：

```json
{
  "query": "那它是不是已经超时了？",
  "chat_id": "chat_001"
}
```

两次请求的 `chat_id` 一样，后端才有机会把它们识别成同一段对话。

前端页面第一次打开时生成一个 `chat_id`。

这次聊天过程中一直复用它。

当用户点击：

```text
新建会话
```

或者刷新后决定重新开始时，再生成新的 `chat_id`。

第一版可以先简单处理：

```text
打开页面
↓
生成 chat_id
↓
整段会话一直使用
```

### 这一步完成标准

连续问两到三轮问题时，前端发送的 `chat_id` 保持一致。

---

# 9. 第九步：处理三种后端结果

前端不要只写一种消息展示。

需要至少处理三种情况。

## 情况一：普通知识库回答

例如：

```text
商品多久发货？
```

后端正常回答。

前端使用普通 AI 消息气泡展示：

```text
普通现货商品通常会在付款成功后的 24 小时内发出。
```

---

## 情况二：订单 / 物流结果

例如：

```text
TEST1003 现在是什么状态？
```

后端通过 MCP 查询到订单数据。

不要只显示一大段文字。

建议转换成订单卡片：

```text
┌─────────────────────────┐
│ 订单号：TEST1003        │
│                         │
│ 订单状态：已发货        │
│ 物流状态：运输中        │
│ 更新时间：16:32         │
└─────────────────────────┘
```

如果当前后端暂时只返回 `answer` 文本，也可以第一版先正常显示文字。

等 MCP 返回结构稳定以后，再增加订单卡片。

也就是说：

```text
第一版先保证能显示
↓
第二步再优化成卡片
```

不要为了卡片重新修改整个后端。

---

## 情况三：无法回答

如果后端返回：

```text
can_answer = false
```

或者：

```text
next_step = human_handoff
```

前端不要显示技术原因。

不要显示：

```text
score_below_threshold
```

而是转换成用户能看懂的内容：

```text
这个问题我暂时无法准确处理，
建议为你转接人工客服。
```

下面显示：

```text
[ 转人工客服 ]
```

### 这一步完成标准

知识库、订单、无法回答三个场景在页面中都有正常展示。

---

# 10. 第十步：实现左侧快捷服务

聊天主流程跑通以后，再处理左侧按钮。

不要一开始就做。

例如点击：

```text
查订单
```

可以自动在输入框中填入：

```text
请输入订单号，例如 TEST1003
```

点击：

```text
查物流
```

可以提示：

```text
请输入需要查询的订单号
```

点击：

```text
退换售后
```

可以直接发送：

```text
我想了解退换货规则
```

这些按钮本质上只是帮助用户更快发起问题。

不要为它们单独设计新的后端系统。

### 这一步完成标准

四个快捷入口可以正常触发对应聊天行为。

---

# 11. 第十一步：增加基本交互状态

主功能完成后，只补最基本的交互。

需要增加：

### 发送中

用户点击发送后：

```text
AI 正在思考……
```

或者显示加载动画。

避免用户连续点击多次。

### 空输入

如果输入框为空，不发送请求。

### 接口失败

如果 FastAPI 没启动或者接口报错：

```text
服务暂时不可用，请稍后重试。
```

不要让页面直接报一堆代码错误。

### 自动滚动

AI 回复后，聊天区域自动滚动到最新消息。

### 这一步完成标准

正常使用时不会出现明显的交互问题。

---

# 12. 推荐的前端目录

第一版目录不要设计得太复杂。

可以使用：

```text
frontend/
├─ src/
│  ├─ api/
│  │  └─ chat.ts
│  │
│  ├─ components/
│  │  ├─ ChatMessage.vue
│  │  ├─ ChatInput.vue
│  │  ├─ QuickMenu.vue
│  │  └─ OrderCard.vue
│  │
│  ├─ types/
│  │  └─ chat.ts
│  │
│  ├─ App.vue
│  └─ main.ts
│
├─ package.json
└─ vite.config.ts
```

每个文件的作用：

### `main.ts`

启动 Vue。

### `App.vue`

整个客服页面。

### `api/chat.ts`

负责调用 `/chat`。

### `types/chat.ts`

定义：

- 请求数据；
- 后端响应；
- 聊天消息类型。

### `ChatMessage.vue`

显示普通聊天消息。

### `ChatInput.vue`

输入框和发送按钮。

### `QuickMenu.vue`

左侧快捷入口。

### `OrderCard.vue`

显示订单 / 物流信息。

第一版如果觉得组件太多，也可以先把部分内容直接写在 `App.vue` 中。

不要为了“架构漂亮”增加很多文件。

# 13. 最终调用链路

完成以后，整个前端链路应该是：

```text
浏览器
↓
Vue 页面
↓
用户输入问题
↓
ChatInput
↓
Axios
↓
POST /chat
↓
FastAPI
↓
ChatService
↓
RAG / MCP
↓
DeepSeek
↓
Answer Reliability
↓
返回 JSON
↓
Axios
↓
messages
↓
ChatMessage / OrderCard
↓
用户看到答案
```

# 14. 实际开发顺序总结

真正开发时，严格按下面顺序做：

```text
1. 创建 Vue + Vite 项目
↓
2. 启动 Vue，确认能打开
↓
3. 安装 Element Plus 和 Axios
↓
4. 做静态客服页面
↓
5. 建立 messages 聊天数据
↓
6. 建立 Axios /chat 接口
↓
7. 解决 CORS
↓
8. 打通“发送问题 → 后端 → 显示回答”
↓
9. 加入 chat_id
↓
10. 测试多轮对话
↓
11. 处理订单 / MCP 结果
↓
12. 处理 can_answer=false / 转人工
↓
13. 增加快捷服务
↓
14. 增加加载、失败提示和自动滚动
↓
15. 完成最终页面
```

不要同时做所有东西。

必须先把最核心链路：

```text
输入问题
↓
POST /chat
↓
显示回答
```

跑通。

然后再一个功能一个功能往上增加。

---

# 15. 做到什么可以结束

这一阶段满足以下条件后就结束：

- Vue 项目可以正常启动；
- 客服主页面完整；
- 用户可以输入并发送问题；
- Axios 可以正常调用 FastAPI `/chat`；
- 知识库问题可以显示 AI 回答；
- 连续对话可以复用同一个 `chat_id`；
- 订单问题可以展示 MCP 查询结果；
- 无法回答时可以显示转人工提示；
- 快捷服务可以使用；
- 页面具备基本加载和错误提示。

完成这些以后，不继续增加：

- 登录注册；
- 商城页面；
- 用户中心；
- 后台管理；
- 知识库管理；
- 人工客服坐席系统；
- WebSocket；
- Pinia；
- 复杂权限；
- 数据统计 Dashboard。

这些全部属于后续版本。
