# 新旧链路现状与清理候选

> 复核日期：2026-09-27
> 范围：当前 `/chat` 与闲鱼专家运行链路。C1、C2 已按清单清理并完成针对性回归检查；C3 经复核仍在使用，保留。

## 当前主链路

```text
POST /chat
→ ChatService.chat_async()
→ SessionManager.load()
→ Planner.plan_async()
   ├─ 兼容路由或安全回退：规则状态 → Task[]
   └─ 语义理解成功：UserNeed[] → Task[]
→ 需要消歧时 ItemContextResolver
→ TaskExecutor → ExpertTaskWorkflow
→ XianyuExpertTaskHandler → Task 转 ExpertTask
→ XianyuExpertOrchestrator.execute_tasks()
→ ProductAgent / PriceAgent / ServiceAgent
→ ResultMerger
→ SessionManager.save_turn()
→ API Response
```

闲鱼专家编排器现在接收 Planner 已经拆好的任务并直接执行；在 `execute_tasks()` 里没有第二次规划。这一点与本文旧版记录的“外层 Planner 和专家编排器重复规划”不同。

## 清理项与处理结果

### [C1｜优先复核：合并双重规划准备路径]

**位置：** `app/services/planner.py` 的 `Planner.plan_async()`、`Planner.plan()`；`app/services/query_planner.py` 的 `build_expert_plan()`。

清理前，`plan_async()` 每轮先调用同步 `plan()`，为闲鱼消息构造规则任务；语义理解成功时，再由 `UserNeed[]` 构造另一份 `Task[]`，前一份任务通常只用于判断是否走语义路径，不会进入执行器。规则状态同时承担两个用途：

- 决定非闲鱼/兼容请求是否跳过语义规划；
- 语义规划故障时，为低风险闲鱼请求提供规则回退。

**处理结果：已完成。** `plan_async()` 现在只构造路线和商品上下文状态；只有走兼容路径或语义理解失败且满足安全回退条件时，才生成规则任务。语义规划成功时不再先构造一份随后被丢弃的完整任务列表。`plan()` 和 `build_expert_plan()` 保留给同步兼容入口与安全回退使用。

### [C2｜低优先级：清理旧会话意图字段]

**位置：** `app/services/session_manager.py` 的 `legacy_intent` 参数和 `last_intent` 状态字段。

当前应用代码只在 `SessionManager` 内写入、规范化和保存 `last_intent`，没有其他运行时代码读取它；`ChatService.save_turn()` 也没有传入 `legacy_intent`。测试仍直接覆盖该兼容字段。

**处理结果：已完成。** 已移除 `append_turn()` 的 `last_intent`、`save_turn()` 的 `legacy_intent` 和默认状态中的旧字段。读取历史会话时会忽略旧 `last_intent`，保留仍在使用的 `last_task_type`。对应旧测试夹具已改为确认历史字段会被忽略。

### [C3｜架构收敛项：两种任务对象]

**位置：** `app/services/chat_contracts.py` 的 `Task`、`app/services/xianyu/experts/contracts.py` 的 `ExpertTask`、`app/services/task_executor.py::to_expert_task()`。

这两种任务类型目前都在主链路中使用，转换适配器是专家执行所需的边界，并非无人调用的旧代码。

**处理结果：保留。** 两种任务对象和转换适配器都仍在主链路使用，不属于可删除的旧代码。

## 不应当列为删除候选的活跃逻辑

- `PriceAgent._legacy_decide()`：`items.json` 中有 4 个商品，其中 3 个没有独立议价政策；这些商品仍会进入兼容定价分支。除非先补齐政策或明确禁用议价，否则不能删。
- `IntentRouter`、`build_question_plan()`、`build_expert_plan()`：仍参与 Planner 的意图元数据、路径选择或回退；不是纯死代码。
- `ItemFactResponder.answer_intent()`：由 `answer_target()` 调用，ProductAgent 和 ServiceAgent 都使用；不是旧的独立回答链。
- `ItemContextResolver`、`TaskExecutor`、`ExpertTaskWorkflow`、`ResultMerger`、`XianyuKnowledgeResponder.prepare_evidence()`：均在当前请求链路中可达，应保留。

## 已经不存在的旧入口

搜索当前 `app/` 后，以下旧入口已不存在，无需再清理：

- `OrderChatHandler.combined()` / `DeepSeekGenerator.generate_combined()`；
- `XianyuKnowledgeResponder.handle_item()`；
- `ItemFactResponder.answer_plan()`；
- 专家编排器内部重新生成整轮计划的旧 `handle()` 入口。

因此，旧版报告中“订单合并入口待删”“旧 `handle_item()` 待迁移”“`answer_plan()` 与 `answer_intent()` 重复”等条目已过期。当前 `ItemFactResponder` 仍通过 `answer_target()` 调用 `answer_intent()`，不能把后者当成死代码删除。
