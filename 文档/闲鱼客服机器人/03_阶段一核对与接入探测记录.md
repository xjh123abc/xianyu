## 1. 阶段结论

### 结论 A：现有业务主链路可以继续增量开发

结论为“可以”，依据如下：

- 当前完整测试集 100 项全部通过，未发现阻断主链路的回归；另有 1 条 Starlette/AnyIO 弃用警告。
- `/chat`、ChatService、RAG、可靠性判断、短期 Memory、MCP 客户端和服务端均有实际代码及测试覆盖。
- MCP stdio 真实子进程 smoke 通过，能够发现并调用 `get_order`；当前工作区还发现了闲鱼阶段二的 `get_item_info`。
- 本地 Embedding、Qdrant、BM25、RRF 和本地 Reranker 完成 58 条检索评估；38 条标注为可答的样例中，Rerank Recall@5=1.0000、MRR=0.9737、Top1=0.9474、Top3=1.0000，未形成继续开发的阻断。
- 阶段一没有修改现有检索、路由、生成或 MCP 业务代码。

可以进入阶段二，但应保留以下已知边界：当前 `SessionManager` 只使用进程内字典，重启即丢失；DeepSeek 生成调用的异常会从普通 RAG 路径传播成 HTTP 500；这两项不是阶段一新增问题，分别应在阶段三持久化工作和后续错误处理工作中解决。

### 结论 B：当前闲鱼账号已实测收到买家文本，发送仍未验证

结论为“登录态、接入通道和买家文本接收已验证，发送仍待实测”。本次 60 秒隔离探测完成登录校验、Token 刷新和 WebSocket 连接，并收到 1 条买家文本事件。当前项目环境中检测到可解析的 `XIANYU_COOKIES_STR`；当前应用开关为 `XIANYU_ENABLED=true`、未设置 `XIANYU_MODE`，真实业务应用仍没有渠道适配代码。没有明确接收会话和账号持有人触发前，不执行发送。

按需求文档口径，阶段二、阶段三和本地页面可以继续推进；阶段四的接收子步骤已通过，但真实发送、发送回执和机器人回流仍保持阻塞。不得把一次接收成功等同于发送闭环或自动回复已完成。

## 2. 当前模块对应与调用关系

| 能力 | 真实位置 | 当前作用 |
| --- | --- | --- |
| FastAPI 应用 | `app/main.py` | 注册 `/chat`，提供 `/health`。 |
| `/chat` API | `app/api/chat.py` | 校验 `query/chat_id`，调用 `ChatService.chat_async`，序列化旧响应字段。 |
| 业务编排与路由 | `app/services/chat_service.py` | 在 `rag/order/rag_mcp/missing_order_id/unsupported_action` 间路由。 |
| RAG 服务入口 | `app/services/rag_service.py` | 组织检索、Rerank、可靠性门控、上下文和生成。 |
| Dense / Qdrant | `app/retrieval/vector_search.py`、`app/infrastructure/qdrant.py` | 本地 Embedding 查询 Qdrant。 |
| BM25 / RRF | `app/retrieval/bm25.py`、`app/retrieval/hybrid_search.py` | 关键词召回及 Dense/BM25 融合。 |
| Reranker | `app/retrieval/reranker.py` | 从配置的本地目录离线加载模型并重排。 |
| 可靠性判断 | `app/rag/answerability.py` | 以首个有效 Rerank 分数和阈值决定继续或转人工。 |
| Context Builder | `app/rag/context_builder.py` | 拼接文本上下文，单独保留来源元数据。 |
| 生成 | `app/generation/deepseek.py`、`app/generation/prompt.py` | 调用已配置的 DeepSeek 兼容接口。 |
| 短期 Memory | `app/services/session_manager.py` | 按 `chat_id` 隔离最近历史和订单状态；当前仅内存保存。 |
| MCP 应用服务 | `app/services/mcp_service.py` | 规范化订单号并隔离工具调用。 |
| MCP 客户端 | `app/infrastructure/order_mcp_client.py` | 启动 stdio 子进程、调用工具、校验结构化结果并关闭连接。 |
| MCP 服务端 | `mcp_servers/order_server.py` | 提供本地模拟订单只读 `get_order`；当前工作区另有闲鱼商品只读工具。 |
| 单元/集成测试 | `tests/` | 覆盖 API、检索、生成、可靠性、MCP、路由和 Memory。 |
| 检索评估 | `eval/retrieval_eval.py` | 执行 Dense、BM25、RRF、Rerank 分阶段评估并保存 JSONL。 |

当前主调用链为：

```text
POST /chat
  -> app.api.chat.chat
  -> ChatService.chat_async
  -> route_query
  -> RAGService 或 MCPService（组合问题并行调用两者）
  -> AnswerReliability
  -> ContextBuilder
  -> DeepSeekGenerator
  -> 原 Response 结构
```

- 可答问题“符合条件的普通商品支持七天无理由退货吗？”能够完成检索和可靠性前置链路，但生成阶段需要把问题和检索上下文发送到配置的外部 DeepSeek 接口。本次未获得对这些具体数据出境的明确授权，因此没有执行外部生成验证；受限网络下的尝试返回连接错误，FastAPI 表现为 HTTP 500。

因此，“有检索结果但无法回答”的历史现象需分两类理解：证据分数不足时是预期的安全拒答；证据足够但外部生成连接失败时是当前错误处理缺口，不是检索失败。
