# 闲鱼客服机器人阶段二实现记录

日期：2026-09-09

## 范围

本阶段只把现有 `POST /chat` 扩展为本地闲鱼商品问答，不连接真实闲鱼消息，也不自动发送消息。

## 已实现

- `data/xianyu/items.json` 保存三件互不相同的演示商品（A/B/C），其中 B 已售出、C 状态未知。
- `data/xianyu/knowledge/` 保存卖家通用规则及每件商品的独立说明。
- 现有 MCP 服务新增只读 `get_item_info(item_id)`；返回公开字段和更新时间，不返回任何内部报价字段。
- 复用 Loader → Chunker → Embedding → Qdrant 入库流程，闲鱼使用独立 `xianyu_documents` collection 和 manifest。
- Dense 使用 Qdrant payload 过滤；BM25 在 Top K 之前过滤；两路只允许通用规则或当前商品资料。
- `/chat` 保留原电商默认行为，新增 `scenario=xianyu` 和可选 `item_id`。
- 价格和售卖状态优先使用 MCP 结构化事实；商品说明和卖家规则使用范围过滤后的 RAG。缺少商品、证据不足和状态未知分别澄清或转人工。
- 组合问题会把价格/状态与知识问题拆开验证：结构化事实由 MCP 确认，剩余问题附加当前商品标题后再检索，最后合并为同一回复；知识不足时保留已确认事实并转人工。
- Windows 下在导入本地 Hugging Face 模型前默认关闭异步权重物化，并在进入 `asyncio.to_thread` 前完成检索模型预热，避免 Reranker 首次在线程池加载时偶发原生级 `access violation`；用户显式配置时不覆盖。
- `.env.example` 已补齐闲鱼商品、知识库、Qdrant collection 和 manifest 配置；内部资料、数据库与日志目录加入 Git 忽略规则。

## 调用链

```text
POST /chat (scenario=xianyu)
  -> ChatService._chat_xianyu
  -> MCPService.get_item_info
  -> RAGService.prepare(item_id=...)
  -> Dense + BM25 (common OR selected item)
  -> existing Reranker / ContextBuilder / DeepSeek
```

## 验证

- `python -m app.ingestion.pipeline --scenario xianyu` 已成功写入 4 个闲鱼知识 chunk 和 `xianyu_documents`；当前 manifest 指纹与本地知识文件一致。
- `python -m scripts.smoke_order_mcp` 已通过，实际发现 `get_order`、`get_item_info`，并通过 stdio 查询 `DEMO_ITEM_001`。
- `python -m scripts.smoke_xianyu_stage2` 已通过 5 个真实本地用例：在售价格、已售状态、未知状态转人工、商品缺失澄清、价格与配件组合回答。该入口实际经过 FastAPI、MCP、Qdrant、Embedding 和 Reranker，但明确不调用外部模型。
- 三件商品分别执行本地 Dense + BM25 + Rerank，结果只包含通用规则和当前商品，未混入另外两件商品。
- 已执行一次真实 DeepSeek 端到端调用：`DEMO_ITEM_001` 的“价格＋配件”请求实际经过 FastAPI、MCP、范围 RAG、本地 Reranker 和 DeepSeek。响应为 `reply / can_answer=true`，包含标价 `¥1280.00`、原厂背带、镜头前后盖和通用电池，来源为当前商品资料与通用规则，Top Rerank 分数为 `6.8125`。
- 阶段二重点测试（商品问答、商品 MCP、Windows 模型加载）共 22 项通过；全量回归 `106 passed`，另有 1 条 Starlette TestClient 弃用警告，不是测试失败。
